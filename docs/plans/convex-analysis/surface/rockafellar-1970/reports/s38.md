## 5. Divergences recorded in docstrings

1. **`□` is unconditionally commutative and associative** (`infConvBifun_comm'`,
   `infConvBifun_assoc'`), where the book hedges "to the extent that it is defined" (16239). The
   backbone's `infConvBifun_comm` / `infConvBifun_assoc` (and `infConvFstBifun_comm` /
   `infConvFstBifun_assoc`) hold for arbitrary bifunctions, improper ones included, because
   `infConv` is a total operation on `EReal`. This is **stronger** than the book — the direction
   `gotchas.md` ER4 warns about, seen from the safe side. The book's caveat that *is* real is about
   bifunction multiplication (16507), and that one is not discharged.
2. **The two `∞ − ∞` conventions are named apart** (`convexAdd`, `concaveAdd`), with
   `convexAdd_top_bot = ⊥`, `concaveAdd_top_bot = ⊤`, `convexAdd_ne_concaveAdd`, and
   `concaveAdd_eq_convexAdd` for the agreement off the two collisions.
   `theorem_38_1_bracket_concave` is **false** with `convexAdd` in its place, which is the concrete
   reason a single notation must not carry both.
3. **Theorem 38.1's domain formula is misprinted** at 16214 as `dom (F₁ ∩ F₂) = dom F₁ ∩ dom F₂`;
   the operation meant is `□`. `theorem_38_1_dom` states the intended identity.
4. **`⟨f, g⟩` is kept partial.** `HasInnerProduct` is an explicit hypothesis wherever an inner
   product is claimed to exist (`lemma_38_6_exists`, `lemma_38_6`, `corollary_38_7_1_exists`,
   `corollary_38_7_2_exists`); `innerProduct` is the inf side and is only Rockafellar's `⟨f, g⟩`
   under that hypothesis.
5. **Corollary 38.7.2's own proof is incomplete** — Rockafellar leaves the `ri (dom (GF))` formula
   "to the reader as a pithy exercise" (16691) — so `corollary_38_7_2_first` carries the
   `IsExactSum` its proof actually consumes.
6. **Corollary 38.4.1 and Corollary 38.5.1 are stated in the backbone's `F⁎*` packaging**, in which
   the right-hand side stays between *convex* bifunctions and no concave closure operation is
   needed. Corollary 38.2.1's `F₁* □ F₂*` becomes an infimal convolution in the **first** variable
   (`infConvFstBifun`) for the same reason.

## 7. Gotchas worth adding

* **`EL`** — `_root_.EReal.neg_add` is stated with a **`Sub`** on the right (`-(x + y) = -x - y`),
  not with `+ -`. `rw [EReal.neg_add h₁ h₂, neg_neg, neg_neg]` therefore fails on the *second*
  `neg_neg`: after the first the goal reads `a - -b`, and EL3's "`Sub` is a separate head from
  `Neg`" applies. Bind the equation in a `have` with the `+ -` type you want
  (`have h : -(-a + -b) = - -a + - -b := EReal.neg_add h₁ h₂`) and rewrite by that. Cost: one build
  cycle in `Rockafellar.concaveAdd_eq_convexAdd`.
* **`LINT`** — `omit … in` must precede the **doc comment**, not sit between the doc comment and
  `theorem`; the latter is a parse error reading `unexpected token 'omit'; expected 'lemma'`. Also,
  the unused-section-variable linter reports only what is unused *given the omits already present*,
  so closing it takes several build cycles: each new `omit` can expose the next unused instance.
  Four cycles on `Bifunction/Cofinite.lean` here.
* **`EL`** — `simpa using h` failed to close a goal differing from `h`'s type only by
  `innerProduct` (a reducible `abbrev` for `fenchelPairing`, itself a `def` for `fenchelInf`); simp
  normalised both sides and then could not match. `rw [flip_pairing] at h; exact h` works, because
  `exact` takes the defeq step that `simpa`'s closing tactic will not.
* **`EL`** — `(continuous_const.smul continuous_fst)` for `fun p : E × F => (l • p.1, p.2)` leaves
  `TopologicalSpace ?m` stuck, because `continuous_const`'s codomain is not determined by the
  expected type of the `Continuous.smul` application. `(continuous_fst.const_smul l).prodMk
  continuous_snd` elaborates.
* **`LIB`** — a line-length check on a surface file must count **codepoints**, not bytes. A
  byte-counting `awk 'length($0)>100'` reports fifty false positives on a file full of `□`, `⁎`,
  `ℝ` and `⟨⟩` that the Lean linter passes clean.
